- 원인: 이미지 placeholder가 검정 / 탭 전환 시 리스트 즉시 비움(items=[]→loading).
- 수정:
  1. 로딩 중 검정 박스 절대 금지 → 연한 다크그레이 skeleton 또는 카드 프레임 placeholder.
  2. 이미지 URL 변경 시 기존 이미지 유지 후 자연 교체(`Image.network gaplessPlayback:true` / CachedNetworkImage 동등 효과).
  3. 탭 전환/정렬 변경 시 기존 리스트 즉시 비우지 말 것(isRefreshing 플래그, 새 데이터 도착 후 교체).
  4. 공통 카드 이미지 위젯(홈/리스트/상세)으로 placeholder 통일. errorWidget도 검정 아닌 "이미지 없음" placeholder.
  5. 성공 기준: 느린 네트워크에서도 검정 빈칸 한 프레임도 안 보임. release 빌드로 영상 재검증.
- 주의: 가격/API/레이아웃 크기 불변. 이미지 로딩 UX·placeholder만.

### B2-2. 스캔 결과 후보 이미지 안 뜸 → **데이터/인덱스 갭 (코드 fix 아님, 출시 비차단, 보류)**

- consumer 폴백(card-back)은 정상. **코드 수정 불가 = 카탈로그/인덱스 이미지 보완(데이터)으로 출시 후 처리.**

### B2-3. 챗방 — 상대가 "그냥 나가도" 메시지 못 보냄 (버그)
- 증상: 상대가 차단/신고가 아니라 단순 "나가기" 했는데도 내가 말을 못 검.
- 정책: **차단/신고만** 입력 차단해야 함. 단순 나가기는 남은 사람이 메시지 가능해야.
- 수정: conversation-state의 `otherLeft → canSendMessage=false` 로직 재검토(나가기는 차단 X). backend `requireOtherNotLeft` + ConversationStateDto.
- 주의: 차단/신고 차단 로직은 유지.

### B2-4. 판매 플로우 — 예약 거쳐야 거래완료

- 정책: **OPEN→RESERVED(거래중, 상대 선택)→COMPLETED** 순서 강제. OPEN→COMPLETED 직접 금지.
- 수정: 상태 변경 메뉴/백엔드 updateStatus 가드.

### B2-5. 거래완료 시 실거래가 시트 즉시 표시
