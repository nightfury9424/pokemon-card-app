## 1. 진입 (오리파 상세)
- 기존 번호 오리파 상세의 **상품판 유지**. 유저는 뽑기 전 번호별 남은 상품/획득된 빈자리를 본다.
- 하단 CTA `[1구 뽑기 · 50,000 P]` 탭 → 즉시 뽑지 말고 **확인 바텀시트**.

## 2. 확인 바텀시트 (오터치/오버셀 가드)
```
1구를 뽑을까요?
사용 포인트    50,000 P
현재 포인트   125,000 P
뽑은 후 잔액   75,000 P
"뽑기를 시작하면 취소할 수 없습니다."
[취소]   [1구 뽑기]
```
- `[1구 뽑기]` 누른 **그 시점에 draw 번호 확정 + 포인트 차감**.
- 결과는 **결정론적**(난수 아님). **애니메이션 도중 결과 결정 금지.**

## 3. draw 시퀀스 & 초기 상태 (결정론)
- 초기 획득번호(taken) = **흩뿌린 고정 37개 set** (STEP 1의 `n<=sold` 연속식 폐기):
  ```
  {1,3,7,11,14,18,20,22,24,26,29,31,33,35,37,39,41,43,45,48,
   50,54,56,58,60,62,64,67,70,72,75,78,81,84,87,91,96}
  ```
  → 시작 = 획득 37 / 남은 63. 47·9·52 는 미획득.
- draw = **1~100 고정 full permutation**, 선두 반드시 `47 → 9 → 52`, 이후 나머지 번호. cursor가 순회하며 **이미 taken이면 skip**, 다음 미획득 번호 확정.
- 앱 재시작 시 초기 taken/커서로 **reset**. 난수 0.
- 남은 63개 전부 소진 시 **"매진"** (`남은 0구`, CTA disabled). **"데모 종료" 문구 금지.**

## 4. 번호 → 상품 (모든 번호가 실 상품)
- **generic "상품" placeholder 금지.** 100번 전부 실제 `OripaPrize`를 가진다.
- 8개 내외 mock 상품 catalog + 여러 번호가 **같은 상품 반복 매핑**(사장님이 수량 넣듯). deterministic.
- 최소 고정: `47=리자몽 ex SAR/280,000P`, `9=피카츄 계열/45,000P`, `52=뮤 ex/18,000P`. 나머지는 catalog 상품에 고정 매핑.
- `OripaPrize { id, name, rarity, imageUrl, exchangePoints }`.

## 5. 상품 이미지 (실 이미지, placeholder 금지)
- `OripaPrize.imageUrl` = **static 문자열 URL**. 레어도배지+placeholder만으로 가지 않는다.
- 기존 카드 CDN의 실 이미지 URL(`{cardCdnBase}/jp/{CRD_id}.png`)을 static 문자열로만 사용.
- ⚠️ **카드 DB lookup / `card_id` FK / 예상가 DB / 자산 도메인 연동 전부 금지.** 오리파 상품 도메인 분리 유지. 이미지는 "사장님이 올린 상품 이미지" mock일 뿐.
- ⚠️ sandbox 네트워크로 200 검증 불가 → **실기기 확인 필요**. 안 뜨면 CardImage가 카드뒷면으로 degrade(깨짐 아님), URL 문자열 1줄 교체로 수정.

## 6. 뽑기 화면 (풀스크린)
- 확정 후 **ShellRoute 밖 새 route** `/oripa/draw/:oripaId`(바텀탭 없음).
- 결과 선택 전까지 **일반 뒤로가기 차단**(PopScope). 뒤로가기 시 안내: "뽑기가 진행 중입니다. 결과를 확인한 뒤 이동할 수 있습니다."
- 상단엔 `남은 N구`만 작게.

## 7. 봉인물 자동 추출 (0.8~1.0s)
- **100칸 그리드 금지.** 화면 중앙에 동일한 봉인물 **8~12장이 실제 카드 더미처럼 겹침**.
- 모션: 더미 살짝 눌림 → 위쪽 몇 장 미세하게 어긋남 → 봉인물 한 장이 앞으로 미끄러져 나옴 → 중앙에 놓임. (직원이 덱에서 꺼내주는 느낌)
- 룰렛/셔플/티어/잭팟/파티클/암전 금지. **스킵 버튼 없음.** 결과와 무관하게 모든 봉인물 외형·추출 모션 동일.

## 8. 덮개 까기 (핵심 손맛)
- 봉인물 = 포개진 카드 2장: 위=덮개 카드 / 아래=일반 RR 카드 + 흰 번호 스티커.
- 유저가 **위 덮개 카드 전체를 잡고 아래로 직접 드래그.** 세로가 기본, 손가락 좌우 이동에 따라 덮개 **-1.2°~+1.2° 미세 회전**(완전 수직 패널 금지).
- **진행 규칙 (스프링백 폐기):**
  - **아래로 단조 진행.** 위로 되덮기 없음. 손가락이 위로 가도 `progress` 감소 금지 → `progress = max(progress, calculated)`.
  - release 시 `progress < 5%` → 원위치(실수터치). `progress ≥ 5%` → **현재 위치 그대로 유지**, 다시 잡아 이어서 깐다.
  - ⛔ **"30% 못 넘기면 처음으로 되돌아가는 스프링백" 금지.** "조금 내리고 멈추고 다시 잡고 또 내리는" 손맛이 핵심.
- **노출 순서 (진행률 기준):**
  | 진행률 | 노출 |
  |---|---|
  | 0~20% | 아래 RR 카드 윗부분 |
  | 20~45% | 흰 번호 스티커 가장자리 |
  | 45~60% | 숫자 일부 (예 "4…") |
  | 60%↑ | 번호 전체 확인 (예 "47") |
  | 82%↑ | 덮개 카드가 아래로 자연스럽게 빠지며 완전 공개 |
- **햅틱:** 60%(번호 전체) `lightImpact` 1회, 82%(완전 공개) `mediumImpact` 1회. **래치(중복 방지). 결과별 차등 없음.**

## 9. 번호 확인 → 상품판 매칭
- 번호 전체 공개 후 **자동 전환 금지.** 약 0.8s 유지 후 하단 `[N번 상품 확인하기]` CTA 노출 → **유저가 직접 탭.**
- CTA 탭 → 기존 오리파 상세 **상품판으로 복귀** → 해당 번호로 **자동 스크롤** → "내 번호" 배지 + 절제된 강조(`scale 1.02`, `translateY -4`). **flip 금지**(상품은 뽑기 전부터 앞면으로 보였음).
- 해당 번호 상품이 판에서 **살짝 들려 나오는 물리 동작** → 그 자리는 "획득됨" 빈자리 → **결과 시트** 노출. 폭죽/잭팟/암전/티어 금지.

## 10. 결과 & 후속 액션
```
[상품 이미지]
{번호}번 상품 · {상품명} · 교환 {P}
[보관하기]   [{P}로 교환]
```
- **보관하기**: 매장별 mock 보관함 세션 내 `+1` → 안내 후 `[다시 뽑기 · 50,000 P]` / `[오리파로 돌아가기]`.
- **포인트 교환**: 세션 mock 포인트에 `exchangePoints` 추가 → 갱신 포인트 표시 → 동일 `[다시 뽑기]` / `[오리파로 돌아가기]`.
- **다시 뽑기**: 누를 때마다 **확인 바텀시트 재표시**(즉시 차감/다음 draw 금지). 잔액 부족 시 `[다시 뽑기]` **disabled + "포인트가 부족합니다"**. 충전은 준비 중 mock.

## 11. 세션 mock 상태
- `OripaSession extends ChangeNotifier` **싱글톤**(`AuthState` 패턴). 화면은 `ListenableBuilder` 구독.
- 보유: `points`(시드 125,000) · `held`(시드) · `Map<oripaId,Set<int>> taken` · `Map<oripaId,int> drawCursor`.
- `남은 N구 = total - taken.length`(파생).
- 뽑기 확정 시 `pricePerDraw` 차감 + 번호 taken 추가. 보관 시 held +1. 교환 시 points += exchangeP.
- **앱 재시작 = 초기값 리셋. 영속/API/DB/원장 0.**

## 13. 뒤로가기 정리
- 확인 시트 전: 일반 뒤로가기 가능.
- `[1구 뽑기]` 확정 후 ~ 결과(보관/교환) 전: **뒤로가기 차단**(§6 안내). 확정 draw 번호는 세션에 유지, 결과까지 보게 함.

## 14. 디자인 원칙 — "가챠 금지 ≠ 디테일 금지"
